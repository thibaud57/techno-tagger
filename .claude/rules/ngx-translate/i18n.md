# ngx-translate — i18n

## À faire
- Configurer par `provideTranslateService()` avec `provideTranslateHttpLoader({ prefix, suffix })`, et fournir `provideHttpClient()` sans quoi le loader ne récupère aucun fichier
- Faire pointer le `prefix` sur l'arborescence réelle du projet
- Importer `TranslatePipe` et `TranslateDirective` composant par composant : il n'y a plus de module
- Lire `currentLang()` comme un Signal, y compris dans un `computed()`, sans abonnement RxJS
- Résoudre la langue initiale depuis la locale système par le plugin `os` de Tauri, en comparant le **préfixe** du tag BCP-47 : commence par `fr` donne du français, tout le reste donne de l'anglais, et `locale()` peut rendre `null`
- Laisser le choix de l'utilisateur, une fois posé dans le `store`, primer sur la locale système aux lancements suivants
- Structurer les clés par feature (`run.summary.title`), en miroir de l'arborescence des composants
- Garder les deux fichiers de langue synchronisés dans le même commit : une clé ajoutée d'un seul côté produit du texte anglais au milieu d'une interface française
- Activer `failOnError: true` en développement

## À éviter
- Importer `TranslateModule` ou appeler `setDefaultLang()` : ils n'existent plus en v18
- Écrire `currentLang` sans parenthèses : c'est un Signal, l'expression est toujours truthy
- `instant()` au démarrage : les traductions ne sont pas chargées et la clé brute s'affiche, préférer le pipe
- Utiliser le texte de l'élément comme clé (`<span translate>HELLO</span>`) : déprécié, suppression annoncée, préférer `[translate]="'HELLO'"`
- Traduire les rapports de run : ils sont en anglais par décision, quelle que soit la langue de l'interface (cf. [ADR-014](../../../docs/adrs/014-observabilite-sentry-et-rgpd.md))
- Coder la langue en dur au bootstrap en ignorant la locale système

## Gotchas
- Renommages en cascade v18 : `defaultLang` → `fallbackLang`, `setDefaultLang()` → `setFallbackLang()`, `onDefaultLangChange` → `onFallbackLangChange`, `DefaultLangChangeEvent` → `FallbackLangChangeEvent`, `useDefaultLang` supprimé et `translate.langs` remplacé par `getLangs()`. Un exemple antérieur à la v18 échoue à la compilation, ce qui est le bon symptôme
- Un 404 sur un fichier de traduction rend `{}` avec un simple warning : un `prefix` erroné produit une interface où toutes les clés s'affichent brutes, sans erreur visible
- `setTranslation()` remplace les traductions au lieu de les fusionner par défaut
- `currentLang` est un `Signal<Language | null>` : `null` avant le premier chargement, et `getCurrentLang()` peut aussi rendre `null`
- La compatibilité OnPush du pipe est annoncée par la documentation officielle, mais une source tierce le décrit comme un pipe impur à base de RxJS : si une traduction ne se rafraîchit pas après un `use()`, c'est la première hypothèse à tester
- Le câblage locale système ↔ langue n'est documenté ni côté Tauri ni côté ngx-translate : c'est une composition des deux API, à couvrir par un test si la logique de repli évolue

## Exemples
```typescript
// ✅ Signal appelé, comparaison sur le préfixe du tag BCP-47
readonly isFrench = computed(() => this.translate.currentLang() === 'fr');

const systemLocale = await locale();            // 'fr-FR' | null
return systemLocale?.toLowerCase().startsWith('fr') ? 'fr' : 'en';

// ❌ Signal lu comme une propriété : toujours truthy
if (this.translate.currentLang) { ... }
```
